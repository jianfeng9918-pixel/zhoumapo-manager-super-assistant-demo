# 周麻婆店长超级助手 V4 项目档案

## 产品定位

不是餐饮后台，也不是普通聊天机器人，而是“周麻婆每个店长手机里的AI区域经理”。

核心闭环：

`经营事实 → 店长语言 → 今日剧本 → 轻量执行 → 证据回传 → 结果复查 → 店长成长`

## 固定演示口径

- 门店：三盛广场演示店；店长：黄店长；日期：8月11日。
- 昨日目标¥100,000，实际¥98,600；晚市少32位顾客，3桌反映等菜久。
- 今日目标¥100,000，08:30预计¥92,000，缺口¥8,000。
- 按每桌约¥320、每桌2.6位顾客换算为约25桌、65位顾客。
- 17:30当前¥62,000，正常应完成¥70,000。
- 会员召回新增12桌31位顾客；预约跟进确认7桌18位顾客。
- 行动后当前金额不变，预计收官提升到¥98,000；21:30实际¥100,600。
- 全部口径均为确定性模拟数据。

## 页面原则

- 首页随时段变化，始终突出一个主要动作。
- 数据优先呈现顾客、桌、订单、菜品份数和金额，不呈现门店综合分。
- 任务页展示经营剧本、责任人、方式、证据和影响。
- 学院在问题发生时给做法，并可一键加入剧本。
- 成长记录只依据已完成任务与证据。
- 区域经理是二级演示角色，只在店长需要下发、验收或求助时出现。

## 行动状态

`AI建议 → 待确认 → 执行中 → 待回传 → AI复查 → 已改善 / 需补充 / 请求帮助`

## 技术边界

- 经营模型集中在 `src/demo-model.ts`，页面与状态流在 `src/Prototype.tsx`，视觉扩展在 `src/prototype.css`。
- 复用受保护的手机直接打开模式、FlowStack、MobileScroll和BottomSheet。
- 使用 `zhoumapo-manager-assistant-v4` 保存进度。
- 不连接真实API，不保存生产凭据，不自动真实发送会员消息，不宣称平台已真实同步。

## 验收标准

- 无讲解可走完“预测缺口—剧本—晨会—召回—回传—改善—收官”。
- 营业前不显示当日实时营业额。
- 当前营业额与预计收官严格区分。
- 主要差距可用顾客、桌、订单或份数理解，并能查看换算依据。
- 区域角色支持下发、接收、执行、回传、验收、退回和求助回复。
- 刷新保留V4状态，重置恢复08:30。
- 320、393、412及Pixel宽度无横向溢出或底部遮挡。
- GitHub Pages子路径和品牌/证据资源无404。
