# 周麻婆店长超级助手终局产品档案

## 1. 产品定位

周麻婆店长超级助手是“每个店长手机里的AI区域经理”，不是餐饮后台，也不是聊天机器人。

普通店长无需掌握指标分析方法，只需完成四件事：

1. 看懂现在发生什么。
2. 确认系统建议是否执行。
3. 拍一张、说一句或确认一次完成行动。
4. 看行动是否真正改善经营结果。

终局产品必须持续闭合：

`数据 → 经营判断 → 可执行行动 → 人工确认 → 证据回传 → 人工验收 → 结果变化`

## 2. 首页原则

- 首屏同时看见经营判断、两条依据、一个主行动、人工确认提示、下一次复查与五栏导航。
- 店长语言优先，例如“晚市少65位顾客”，不用“流量指数75”或“转化率下降3.5%”。
- 一屏只出现一个红色一级按钮。
- 当前营业额、预计收官和预计影响严格分开。
- 不展示健康值、六维评分、综合分与大面积数据矩阵。
- 店长日常主线不展示订货与排班；未来仅通过动作与适配器扩展。

## 3. 三角色终局分工

### 店长

负责确认、执行、回传与求助。AI可以预填，但不能代表店长正式下发或申请资源。

### 区域经理

负责门店支持、补充行动、证据人工验收、退回补充与向总部升级。首页先显示必须介入事项，不先显示区域大盘。

### 总部经营中心

负责识别跨区域重复问题、维护指标字典与行动模板、校准AI规则、处理资源需求。AI草稿未经业务人员确认不得发布。

## 4. 唯一主故事

| 时间 | 发生什么 | 谁确认 | 系统结果 |
|---|---|---|---|
| 08:30 | 晚市预计少65位顾客 | 黄店长 | 进入3分钟晨会 |
| 08:45 | AI转写、查漏并预生成3项行动 | 黄店长 | 行动正式下发并收到回执 |
| 16:20 | 会员召回与区域支持申请 | 黄店长 | 进入执行；林阳收到完整上下文 |
| 16:28 | 区域补充曝光或向总部升级 | 林阳 | 新行动同步店长 |
| 17:02 | 店长回传触达与预约证据 | AI初验 | 状态进入待人工验收 |
| 17:08 | 区域确认或退回证据 | 林阳 | 预测结果变化或店长补充证据 |
| 17:10 | 总部修订会员召回模板 | 总部经营中心 | 新版本同步，旧版本与审批记录保留 |
| 21:30 | 收官复盘 | 黄店长 | 生成日报和明日第一件事 |

## 5. 明确边界

- 本版不连接真实BI、POS、美团、抖音、会员、预约、企微或审批接口。
- 本版不自动处罚员工、不自动付款、不自动发布内容、不自动批准资源。
- 本版不展示订货与排班，但模型允许后续新增动作模板和对应适配器。
- 全量数据持续标注“演示数据”。
- 三角色均为手机版并共享同一状态，不复制三套任务数据。

## 6. 成功标准

日华无需重新定义产品模型即可替换模拟适配器；演示者无需讲解即可走完“判断—确认—执行—求助—支持—验收—总部校准—结果复盘”。
