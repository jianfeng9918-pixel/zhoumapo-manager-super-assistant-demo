# 周麻婆店长超级助手 V3 项目档案

## 产品定位

不是餐饮管理后台，而是“AI经营教练 + 门店操作台”。不懂经营方法的店长只需看经营结果、点少量按钮、拍一张照片或说一句话，系统负责判断、拆解、追踪和反馈。

核心闭环：

`经营数据 → AI判断 → 行动建议 → 任务执行 → 证据回传 → AI初验/区域验收 → 经营结果`

## 固定演示口径

- 店长：黄店长 · 三盛广场演示店 · 8月11日。
- 区域经理：林阳 · 福州区域 · 6家模拟门店。
- 默认时点：08:50；初始当前营业额 ¥8,600，预计收官 ¥92,000，门店健康 73。
- 晚市纠偏基准：16:20 当前 ¥63,800，目标 ¥100,000，预测缺口 ¥8,000。
- 行动完成：当前金额不变，预计收官提升至 ¥98,000，健康值提升至 76。
- 实际收官：¥100,600，健康值 80。
- 全部金额、人员、评价、库存、渠道与影响均为演示数据。

## 店长全天主线

| 时段 | 经营状态 | 首要行动 | 完成后的系统变化 |
|---|---|---|---|
| 08:50 | 开店准备 | 开 AI 晨会 | 任务下发并进入午市 |
| 11:30 | 午市低于预测 | 拍照巡检 | 整改闭环并进入午后诊断 |
| 14:30 | 流量恢复、客单异常 | 查看 AI 诊断 | 锁定晚市纠偏动作 |
| 16:20 | 预计缺口 ¥8,000 | 主动推荐训练 | 预计收官升至 ¥98,000 |
| 17:00 | 库存风险 | 采购、沽清与渠道同步 | 解除超卖/退单风险 |
| 21:30 | 实际达成 ¥100,600 | 收官复盘 | 生成日报与明日首项 |

## 六维健康

- 流量 15%。
- 转化 15%。
- 客单 25%。
- 口碑 15%。
- 成本 15%。
- 人员 15%。

每个指标必须呈现异常、原因链、关联数据、数据来源、更新时间、AI置信度、预计影响、行动难度/耗时和复查时间。任务完成后必须更新对应维度、预测业绩或异常数量。

## 任务与状态

任务来源：必做任务、总部任务、区域任务、AI推荐、自主领取、我下发。

状态口径：

`待处理 → 已接收 → 执行中 → 待回传 → 待验收 → 已完成 / 需整改 / 需帮助`

任务卡展示责任人、截止时间、证据要求、催办次数、经营贡献和成长值。任务地图只突出当前一个主节点，完成后由 AI 重新排序。

## 双角色联动

1. 林阳看到三盛预计缺口并语音下发晚市任务。
2. 黄店长收到提醒和区域任务，接收后分发给前厅4人。
3. 黄店长拍照回传，AI先检查人员、动作和照片质量。
4. 林阳查看证据并选择确认闭环或退回补拍。
5. 确认后店长端同步成长值、预计收官和下一项。
6. 黄店长求助时，AI自动附上数据与已做动作；林阳可直接回复或转总部职能。

## 数据与技术边界

- 模拟模型集中在 `src/demo-model.ts`，应用流在 `src/Prototype.tsx`。
- 使用 `zhoumapo-manager-assistant-v3` 保存演示状态，不读取 V2 状态。
- 复用受保护的 `FlowStack`、`MobileScroll`、底部弹层和直接打开模式。
- AI、语音、拍照、平台同步、员工回执、供应商和区域回复全部为确定性模拟。
- 不连接真实 API，不存放生产凭据，不自动处罚员工，不自动付款。

## 验收标准

- 无讲解可走完店长全天主线与一条跨角色任务闭环。
- 晨会、巡检、诊断、采购、人事、沽清、经营提升、提醒与收官均可进入下一步。
- 区域任务支持接收、执行、回传、确认与退回补拍；求助支持跨角色回复。
- 刷新保留 V3 进度，重置恢复 08:50。
- 320、393、412 和 Pixel 宽度下无页面横向溢出或底部遮挡。
- GitHub Pages 子路径、品牌资源和照片资源无 404。
- 线上始终显著标注“演示数据”。
