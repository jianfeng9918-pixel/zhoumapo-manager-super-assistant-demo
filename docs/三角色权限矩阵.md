# 三角色权限矩阵

## 权限原则

AI不是第四个审批角色。AI可以分析、预填、生成、初验、提醒和追踪，但所有外部或正式状态变化必须绑定人类 `ApprovalRecord`。

| 能力 | 店长 | 区域经理 | 总部经营中心 | AI |
|---|---|---|---|---|
| 查看本店经营判断 | 是 | 是（管辖门店） | 聚合查看 | 生成判断 |
| 正式下发门店行动 | 人工确认 | 可下发补充行动 | 通过模板影响 | 仅预生成 |
| 执行动作与回传证据 | 是 | 不代替店长 | 否 | 检查完整性 |
| 向上申请资源 | 发起并确认 | 回复或转总部 | 回复总部资源 | 预填上下文 |
| 证据正式验收 | 否 | 是 | 可审计 | 仅初验 |
| 退回补充 | 否 | 是 | 是（总部需求） | 建议退回原因 |
| 修改指标字典 | 否 | 提建议 | 是 | 发现口径冲突 |
| 修改行动模板 | 否 | 提建议 | 是 | 生成草稿 |
| 发布策略版本 | 否 | 否 | 人工确认 | 不允许 |
| 处罚、付款、预算审批 | 不在本版 | 不在本版 | 不在本版 | 严禁 |

## 权限落地规则

1. `ActionInstance.released=true` 前必须存在动作或决策审批记录。
2. `WorkRequest` 从 `draft` 进入正式流转前必须存在店长审批记录。
3. `Evidence` 经AI通过后只进入 `pendingHumanReview`，不得直接 `closed`。
4. `ActionTemplate.version` 增加前必须存在总部发布审批记录。
5. 所有角色读取同一实体ID，禁止复制门店端、区域端和总部端三套状态。
