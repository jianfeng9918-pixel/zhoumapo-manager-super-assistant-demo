# 日华开发接续指南

## 1. 本地启动

```bash
npm ci
npm run dev -- --port 4173
```

生产与发布包：

```bash
npm run check:runtime
npm run test:runtime
npm run verify
```

## 2. 替换模拟数据的顺序

1. 保留 `src/domain/types.ts` 与 `src/domain/reducer.ts`。
2. 在 `src/adapters/` 新增真实实现，不直接改页面组件。
3. 先替换 `BusinessDataAdapter`，接入指标字典、POS、预约和会员。
4. 再替换 `WorkflowAdapter`，接入企微任务、审批和消息。
5. 再替换 `KnowledgeAdapter`，接入总部SOP与案例。
6. 最后替换 `DecisionEngineAdapter`，接入真实AI与规则引擎。
7. 在 `src/adapters/index.ts` 切换实现，角色页面不应读取任何模拟常量。

## 3. 必须保留的安全约束

- 对外发送、行动下发、资源申请、证据验收与策略发布必须由后端校验审批记录。
- AI输出需要保存模型/规则版本、输入证据、置信度和复查时间。
- 实际营业额只来自权威交易数据；预测和预计影响使用独立字段。
- 模板版本不可覆盖历史，行动实例始终引用执行时版本。
- 区域对标必须匿名。

## 4. 未来订货与排班扩展

本版不展示订货与排班。扩展时：

- 新增对应 `ActionTemplate`，不要在首页新增独立宫格。
- 订货对接库存/供应商接口仍走 `WorkflowAdapter`，付款必须独立审批。
- 排班对接人事/考勤接口，AI只给建议，店长或人事确认后生效。
- 两者产生的经营影响继续回到 `BusinessSignal` 与 `DailyReview`。

## 5. 测试要求

- 保留8项手机运行框架测试，不修改受保护运行框架锁。
- 真实适配器需要增加超时、失败重试、幂等、权限和审计测试。
- 任何新核心按钮必须有可见结果或明确失败反馈。
- 320、393、412、427宽度持续验证无横向溢出，触控区不小于44px。
