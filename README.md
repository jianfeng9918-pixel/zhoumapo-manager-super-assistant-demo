# 周麻婆店长超级助手 V7 · 经营报告与行动效果中心

V7 在 V6“一日经营陪跑”主线不变的基础上，把“数据”升级为真正的经营报告中心：不是新增一组 BI 图表，而是让店长从一句经营结论进入证据、趋势、原因、行动和效果复查。

## V7 新增价值

- 八类经营报告：今日战报、7日复盘、本月目标、客流桌数、菜品经营、顾客口碑、会员经营、行动效果。
- 自然语言问数：直接回答“今天能不能达标”“为什么顾客少”“哪道菜值得推荐”“哪项行动有效”。
- 报表转行动：店长人工确认后才加入今日经营剧本，AI不会自动下发。
- 行动效果账本：严格区分预计影响、新增预约、实际到店和实际营业。
- 分角色报告：区域经理看跨店缺口与介入优先级；总部看有效方法与案例沉淀依据。
- 报告交付：可模拟生成长图、店长日报、7日复盘和90秒语音简报；只生成草稿，不自动外发。

新状态键为 `zhoumapo-manager-assistant-final-v3`，不会读取或覆盖 V2—V6 的演示进度。

完整说明见 [V7经营报告与行动效果中心](docs/V7经营报告与行动效果中心.md)。

## V6 基线：一日经营陪跑终局版

这是基于已选定第3张视觉稿实现的手机版全天经营陪跑 Demo，同时保留日华可继续替换真实数据与工作流的接口契约。

> 全部门店、金额、顾客、预约、会员、员工、证据、渠道结果与AI结论均为确定性演示数据。AI只负责分析、预填、生成、初验和追踪；正式下发、资源申请、人工验收与策略发布都需要人工确认。

## 这版解决什么

系统不是 BI、待办和功能入口的集合，而是三个角色共用的唯一经营入口：

`发现问题 → AI生成建议 → 人工确认 → 执行 → 回传证据 → AI初验 → 人工验收 → 总部校准 → 结果复盘`

- 店长：只看当前判断、一个主行动和下一次复查。
- 区域经理：只看必须介入的门店、待验收证据和店长求助。
- 总部经营中心：只看跨区域重复问题、行动模板和向上资源需求。

## 固定全天故事

1. 08:30：昨日¥98,600，今日预计¥92,000，预计少25桌、65位顾客。
2. 08:45：AI晨会转写、查漏和预生成人员行动；黄店长确认后才下发。
3. 12:00：拍一张午市现场，AI识别等菜与人员问题，不填写巡检表。
4. 14:30：晚市预约少11桌，店长人工确认经营剧本。
5. 17:30：会员召回和预约跟进补回19桌、49位顾客；预计升至¥98,000，当前收入不虚增。
6. 区域经理处理求助和人工验收；总部只在案例沉淀与策略发布节点出现。
7. 21:30：按真实完成情况生成收官结果；未闭环时不会固定显示¥100,600。

## 代码结构

```text
src/domain/                     统一领域模型、Reducer状态机与选择器
src/adapters/                   四类接口契约与确定性模拟实现
src/features/store-manager/     店长端五栏与经营主线
src/features/regional-manager/  区域经理介入、求助与人工验收
src/features/headquarters/      总部策略、区域问题与资源需求
src/features/shared/            三角色共享Provider与UI组件
src/Prototype.tsx               三角色懒加载入口
```

受保护的 `MobileRuntime / FlowStack / MobileScroll / Keyboard / 安全区` 未修改。三角色业务页面已通过动态导入拆包；移动运行时与公共依赖仍在主入口，当前生产构建会提示约510kB的非阻断体积警告。
