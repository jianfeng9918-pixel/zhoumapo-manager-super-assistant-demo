# V7 经营报告与行动效果中心

## 1. 产品目标

经营报告不是 BI 看板的移动版，而是“经营判断的证据页”。每一份报告固定回答：

1. 发生了什么。
2. 对经营意味着什么。
3. 为什么这样判断。
4. 现在应该做什么。
5. 动作完成后有没有真实改善。

首页的一日经营陪跑保持不变，详细数据只从“数据”页按需进入。

## 2. 店长报告中心

| 报告 | 店长首先看到 | 可采取行动 |
|---|---|---|
| 今日经营战报 | 预计收官、桌数与顾客缺口 | 加入会员召回行动 |
| 7日经营复盘 | 问题重复发生在哪几天 | 固化弱晚市剧本 |
| 本月目标进度 | 月度缺口由几个具体晚市造成 | 生成重点日期行动 |
| 客流与桌数 | 顾客具体少在哪个环节 | 召回会员与预约跟进 |
| 菜品经营 | 产品问题还是员工推荐问题 | 生成一句话推荐训练 |
| 顾客口碑 | 等菜、服务还是口味问题 | 生成现场体验复查 |
| 会员经营 | 触达、回复、预约与到店完整漏斗 | 生成召回与实际到店复查 |
| 行动效果 | 哪项动作有真实结果 | 复用、补证据或停止 |

每份报告都显著标注模拟数据来源、更新时间、AI置信度、换算口径和复查时间。

## 3. 行动效果账本

同一行动保留四个不同口径：

- `expected`：执行前的预计影响。
- `measuring`：已有触达或预约结果，但尚未确认真实到店。
- `verified`：通过 POS 或现场复查确认真实结果。
- `actualRevenue`：只有真实结果回链后才允许出现，预测不会直接增加实际营业额。

示例：今日会员召回在区域验收后只记录“新增预约12桌、31位顾客”，实际营业仍为0；21:30收官复查后，才记录实际到店和实际营业。

## 4. 三角色报告

- 店长：本店发生什么、差多少、下一步做什么。
- 区域经理：六家店谁最需要介入、卡在哪一步、哪项行动可跨店复用。
- 总部：哪些问题重复发生、哪些动作已有真实结果、哪些案例可进入正式策略。

三角色使用同一经营状态、行动证据和审批记录，不复制不同版本的事实。

## 5. 生产接口契约

`ReportingAdapter` 统一提供：

- `listReports(scope, state)`：按店长、区域、总部返回报告目录。
- `getReport(reportId, scope, state)`：返回结论、证据、趋势、原因链和行动建议。
- `answerQuestion(questionId, state)`：自然语言经营问数。
- `generateExport(reportId, kind, state)`：生成长图、日报、周报或语音简报草稿。

本版由确定性模拟适配器实现；真实系统替换适配器即可接入 POS、会员、评价、预约与 BI。

## 6. 人工确认边界

- AI可以生成报表、解释数据和预填行动。
- 报表转行动必须由店长确认。
- 报告外发只生成草稿，不自动发送到真实群。
- 区域验收与总部策略发布必须由对应角色人工确认。
