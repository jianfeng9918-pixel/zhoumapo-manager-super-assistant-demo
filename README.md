# 周麻婆店长超级助手终局版 · AI经营操作系统

这是基于已选定“AI对话卡与行动卡融合型”视觉实现的手机版终局可点击 Demo，同时交付日华可继续替换真实数据与工作流的生产级接口契约。

> 全部门店、金额、顾客、预约、会员、员工、证据、渠道结果与AI结论均为确定性演示数据。AI只负责分析、预填、生成、初验和追踪；正式下发、资源申请、人工验收与策略发布都需要人工确认。

## 这版解决什么

系统不是 BI、待办和功能入口的集合，而是三个角色共用的唯一经营入口：

`发现问题 → AI生成建议 → 人工确认 → 执行 → 回传证据 → AI初验 → 人工验收 → 总部校准 → 结果复盘`

- 店长：只看当前判断、一个主行动和下一次复查。
- 区域经理：只看必须介入的门店、待验收证据和店长求助。
- 总部经营中心：只看跨区域重复问题、行动模板和向上资源需求。

## 固定演示故事

1. 黄店长08:30看到“晚市预计少65位顾客”。
2. 开晨会，AI转写、查漏、预填负责人；黄店长确认后才下发。
3. 黄店长确认执行会员召回，并人工确认向林阳申请支持。
4. 林阳回复补充行动；黄店长回传系统证据，AI先初验。
5. 林阳人工确认或退回补充；通过后预计收官由¥92,000升到¥98,000，当前收入不虚增。
6. 总部看到多个区域重复出现晚市顾客不足，业务人员人工发布策略v4.0。
7. 21:30复盘目标、预测、实际与动作效果，生成明日第一件事。

## 代码结构

```text
src/domain/                     统一领域模型、Reducer状态机与选择器
src/adapters/                   四类接口契约与确定性模拟实现
src/features/store-manager/     店长端五栏与经营主线
src/features/regional-manager/  区域经理介入、求助与人工验收
src/features/headquarters/      总部策略、区域问题与资源需求
src/features/shared/            三角色共享Provider与UI组件
src/Prototype.tsx               三角色懒加载入口
```

受保护的 `MobileRuntime / FlowStack / MobileScroll / Keyboard / 安全区` 未修改。三角色通过动态导入拆包，主入口不再出现大于500kB的业务单包警告。

## 本地运行

```bash
npm ci
npm run dev -- --port 4173
```

完整验收：

```bash
npm run check:runtime
npm run test:runtime
npm run verify
```

终局版只使用本地存储键 `zhoumapo-manager-assistant-final-v1`，不会读取或覆盖V2、V3、V4进度。
