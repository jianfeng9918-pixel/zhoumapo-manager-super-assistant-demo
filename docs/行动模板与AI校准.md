# 行动模板与AI校准底稿

## 1. 业务部门填写字段

| 字段 | 说明 | 必填 |
|---|---|---|
| 模板名称 | 店长能理解的动作名称 | 是 |
| 维护部门 | 总部业务责任部门 | 是 |
| 适用条件 | 什么情况下可推荐 | 是 |
| 禁用条件 | 什么情况下禁止推荐 | 是 |
| 执行步骤 | 3–5个店长动作 | 是 |
| 证据要求 | 照片、语音、文字或系统回执 | 是 |
| 预计影响 | 顾客、桌数、金额或体验结果 | 是 |
| 复查时间 | 何时判断是否有效 | 是 |
| 风险边界 | AI不能自动做什么 | 是 |
| 版本与发布人 | 版本、确认人、发布时间 | 是 |

## 2. 示例：晚市会员召回v3.0

- 维护部门：总部市场中心。
- 适用：晚市预计少30位以上顾客；可触达会员超过100人。
- 禁用：门店承载不足；会员当天已触达。
- 步骤：筛选近60天到店会员 → 店长确认召回内容 → 30分钟后回收预约。
- 证据：触达人数回执 + 新增预约。
- 预计影响：补回12至20桌。
- 复查：发送后30分钟。
- 边界：AI不得代表店长发送，不自动发券或产生预算。

## 3. AI校准草稿v4.0

从6家门店复盘发现：旧模板只统计发送量，缺少实际到店复查。

拟新增：

1. 筛选近60天到店且7天未触达会员。
2. 店长人工确认门店专属内容。
3. 30分钟后回收预约，收官时回收实际到店。

新增证据：`触达回执 + 新增预约 + 实际到店`。

只有总部业务人员生成 `ApprovalRecord(decision=published)` 后，版本才从v3.0升到v4.0。

## 4. 防止AI套话的校准规则

- 每条建议必须关联一个 `BusinessSignal`。
- 必须说明负责人、完成时间、证据和复查时间。
- 必须翻译成顾客、桌数、订单、份数或金额。
- 无门店资源时必须提供“向上申请支持”路径。
- 业务部门可设置禁用条件，优先级高于AI建议。
