# 接口契约、状态机与数据流

## 1. 核心领域对象

源码以 `src/domain/types.ts` 为准：

- `MetricDefinition`：集团唯一指标名称、公式、粒度、来源、负责人和店长语言。
- `BusinessSignal`：发生什么、差多少、影响谁、证据、置信度与触发规则。
- `DecisionCase`：AI判断、依据、建议动作、确认人、版本与复查时间。
- `ActionTemplate`：总部维护的标准动作及适用/禁用条件。
- `ActionInstance`：门店当日真实行动、负责人、状态、证据和审批。
- `WorkRequest`：店长向区域或总部提出的资源与职能需求。
- `Evidence`：照片、语音、文字或系统回执及AI初验结果。
- `ApprovalRecord`：人工确认、验收、退回或发布记录。
- `BenchmarkSnapshot`：匿名优秀门店、区域平均、理论标准及店长语言差距。
- `DailyBrief / DailyReview`：全天经营判断与复盘统一输入输出。
- `OperatingSnapshot`：每个经营阶段的当前收入、正常进度、预测、顾客/桌数缺口与复查时间。
- `GapProgress / ActionImpact`：每项行动追回的顾客、桌数与预测提升；`actualRevenueLift`固定为0。
- `KnowledgeCase`：品牌方法来源、适用/禁用条件、证据、审核状态与版本。
- `GrowthEvidence`：成长标签、趋势、关联行动与证据，不使用抽象能力总分。
- `LiveOperatingFrame / MetricTransition`：当前实际、正常进度、预测、缺口、更新时间及变化触发原因。
- `VoiceSession / VoiceIntent`：长按、转写、意图、置信度、取消及待人工确认状态。
- `VisualReport / StoryMedia`：结论、三项证据、趋势分段、图片来源、原因链和唯一推荐行动。

## 2. 统一状态机

```text
detected
  → aiSuggested
  → pendingConfirmation
  → inProgress
  → pendingEvidence
  → aiReview
  → pendingHumanReview
  → closed

异常分支：returned / helpRequested / cancelled
```

中文界面映射：

`发现问题 → AI建议 → 待人工确认 → 执行中 → 待回传 → AI初验 → 待人工验收 → 已闭环 / 退回补充 / 请求帮助 / 已取消`

## 3. 四类适配器

### BusinessDataAdapter

未来接入BI、POS、评价、会员与预约：

```ts
interface BusinessDataAdapter {
  getInitialState(): TerminalState;
  getMetricDictionary(): Promise<MetricDefinition[]>;
  refreshSignals(): Promise<BusinessSignal[]>;
  getSnapshot(stage: OperatingStageId, state: TerminalState): Promise<OperatingSnapshot>;
  getLiveFrame(stage: OperatingStageId, state: TerminalState): Promise<LiveOperatingFrame>;
  subscribeLiveFrames(listener: (frame: LiveOperatingFrame) => void): () => void;
  buildClosingReview(state: TerminalState): Promise<DailyReview>;
}
```

### ReportingAdapter / VoiceInteractionAdapter

```ts
interface ReportingAdapter {
  getVisualReport(reportId: ReportId, scope: ReportScope, state: TerminalState): Promise<VisualReport>;
}

interface VoiceInteractionAdapter {
  resolveIntent(session: VoiceSession, context: "today" | "data" | "tasks" | "academy"): Promise<VoiceResolution>;
}
```

语音解析不得直接调用工作流。只有用户确认预填结果后，页面才能向 `WorkflowAdapter` 提交正式请求。

### WorkflowAdapter

未来接入企微任务、审批、消息与系统回执：

```ts
interface WorkflowAdapter {
  issueActions(actions: ActionInstance[]): Promise<Receipt[]>;
  submitEvidence(evidence: Evidence): Promise<Receipt>;
  submitWorkRequest(request: WorkRequest): Promise<Receipt>;
  publishTemplate(template: ActionTemplate): Promise<Receipt>;
}
```

### DecisionEngineAdapter

未来接入真实AI、规则引擎与证据识别：

```ts
interface DecisionEngineAdapter {
  analyzeMeeting(): Promise<MeetingAnalysis>;
  inspectEvidence(evidence: Evidence): Promise<AIInspection>;
  explainSignal(signal: BusinessSignal): Promise<SignalExplanation>;
  judgeStage(snapshot: OperatingSnapshot): Promise<StageJudgment>;
  recalculateGap(state: TerminalState): Promise<GapProgress>;
}
```

### KnowledgeAdapter

未来接入总部SOP、优秀案例与历史复盘：

```ts
interface KnowledgeAdapter {
  matchProblem(topic: "traffic" | "rating" | "people"): Promise<KnowledgeMatch>;
  matchCurrentCase(state: TerminalState): Promise<KnowledgeCase>;
  listCases(): Promise<KnowledgeCase[]>;
}
```

## 4. 数据流

```text
BI/POS/预约/会员
  → BusinessDataAdapter
  → BusinessSignal
  → DecisionEngineAdapter
  → DecisionCase（AI建议）
  → ApprovalRecord（人工确认）
  → ActionInstance
  → WorkflowAdapter
  → Evidence
  → AI初验
  → ApprovalRecord（区域人工验收）
  → DailyReview / 总部重复问题
  → ActionTemplate新版本（总部人工发布）
```

## 5. 不变量

- 没有 `ApprovalRecord`，对外动作不得显示“已下发”或“已执行”。
- AI初验不等于人工验收。
- 预计影响只能改变预测，不得直接改变当前营业额。
- 指标名称、公式和来源只能由统一指标字典提供。
- 模板更新必须版本化，旧动作继续保留旧版本与审计记录。
- 手动跳到收官只改变观察时段，不得跳过关键行动或生成成功结果。
- 区域支持未回复或被转总部未处理时，剩余缺口不得显示为已追回。
